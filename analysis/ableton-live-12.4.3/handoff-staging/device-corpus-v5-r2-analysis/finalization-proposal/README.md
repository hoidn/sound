# Private finalization design

Design only; no final package is built and no frozen R1/R2 payload is changed.
[proposal.json](proposal.json) identifies exactly five paths for a separately
authorized final tree: README.md, REVIEW.md, spec.md, cases.json and manifest.json.
The independent finite handoff review is still a null dependency here; no new
handoff approval, reviewer identity or final date is assumed.

The actual Root-selected run is complete. Its retained summary reports 73
reference-self evaluations and 4,799 measurements, comprising the earlier 4,795
and four new checks; 38 fixed controls and three strict reference guards match.
There are 311 tiny nonzero self-errors. These are measurement/integration results
from copied references, not a candidate device or compatibility grade. The
existing source code and numerical limits do not change. Root's actual receipts
and run payloads are pinned in [providers.json](providers.json); the exact stored
result metadata was read without recomputing any audio metric.

Only current status, result/provenance and review metadata would change once the
forthcoming review is approved and Root authorizes finalization. All 73 evaluation
objects, 82 F32 files, old 26 group objects, AGENTS and the 9,969-byte comparator
remain unchanged. The new group027's pending provenance can then be updated as
metadata; its evaluation is immutable. All normative criteria, budgets, windows,
histories, exclusions and 174+2 modal omissions remain literal.

The proposed separate final tree is `device-corpus-v5-final`; Root can select its
exact location. Its final inventory would remain 88 payloads/89 files. Only four
text-payload hashes and the manifest itself should change. A focused independent
final seal would precede Root-only exact local publication. This proposal neither
performs that step nor modifies a shared document, source, release or stage.

No metric/evaluator/comparator, fit/FFT/model, audio decoder, native/original or
candidate code was executed for this design. The actual-results review underway
in a separate context owns numerical correctness and handoff approval; this
proposal is not a substitute for it.
