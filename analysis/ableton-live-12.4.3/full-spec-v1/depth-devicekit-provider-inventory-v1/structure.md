# Retained DeviceKit provider inventory — v1

This is one bounded provider frontier supporting the approved Filter/EQ, Dynamics and Distortion maps. It selects **37 retained call/tail-jump occurrences, 27 lexical EXTERNAL symbols and seven template class families**. It establishes **no actual Mach-O provider binding**, provider image, processing body, constructor role, same-instance association or application behavior. All unsupported required behavior remains U and family/product coverage remains OPEN. Counts here are metadata inventory, never outcome, site or grade credit.

The exact target-only query and exclusions are in `query-census.json`. `boundary-rows.jsonl` preserves every selected approved-map wrapper once, with parent line/index/byte-range/hash and its inherited original call-index locator. `symbols.json` groups those occurrences without adding raw rows. The selected target families are AutoFilter2Device, ChannelEqDevice, LimiterDevice, Erosion2Device, Redux2Device, RoarDevice and SaturatorDevice. Method labels such as Init, Exit, CalcMain and constructor-like names remain lexical labels. No method body or callee was expanded.

The approved source context is inherited: predecessor manifests and independent reviews are pinned in `pins.json`; the canonical routing/approval pages and three complete structures are as-of context pins. Their requirement/case decomposition, original index authority, class associations, source semantics and public-route unknowns were not re-audited. The 431 MB original calls index was neither scanned nor rehashed. Selected row source locators remain exact inherited locators, not a fresh read of that index. This packet freshly checked the selected parent metadata records and the bounded package/helper document projections only.

`package-associations.json` separates seven current preset/schema profiles and fourteen content-directory strings from executable identity. Neither a schema root nor a preset directory proves a native provider. The Live service record identifies a consumer executable; the known universal and thin consumer images were only statted, never opened or freshly hashed. Their listed hashes are inherited. No DeviceKit provider candidate image was identified. Three explicit legacy helper sets (Amplifier, Tension and Collision) each contribute only summary, slice and index-manifest metadata. Their source-to-slice associations do not associate DeviceKit with those bundles; listed helper indexes were not opened. The retained helper batch is an analyzed-helper inventory, not a complete package/library inventory.

Five canonically linked legacy metadata inputs are missing at their exact paths (`missing-frontier.json`). The retained main-C1 manifests list strings, calls, indirect, vtables and aliases; they supply no selected consumer import ordinal, dylib install-name, rpath resolution or provider implementation association. EXTERNAL and the C++ namespace are analysis labels, not proof of a Mach-O binding. No match in these bounded documents is an input gap, not provider absence or infeasibility.

`missing-frontier.json` names each residual join and one **unselected proposal**: a staged 32-byte thin-consumer header and capped load-command region, at most 65,568 bytes and 512 commands, to inventory install-names/rpaths and table locations. Nothing in that proposal was read. Header/load commands alone would not bind the 37 call occurrences to providers. Symbol/bind/indirect-table ranges or candidate libraries would require a separately selected frontier; there is no automatic source/callee/global/native expansion.

The selected retained raw units are 37 call wrappers, seven current profile records, fourteen directory strings, one service record and nine shallow helper documents: 68 units, below the 512-row cap. Symbol groups and path projections are derived views, not extra observations. Identified provider paths are zero; two consumer-image frontiers and three explicitly non-associated legacy helper source paths are separately labelled, all within the 16-path cap. `read-budget.json` conservatively charges complete logical document sizes for earlier excerpts and a failed overbroad display query, and reserves one complete pin-check pass below 4 MiB. No binary or new C-body bytes were read; no provider/decoder/native/original/model/comparator/fixture/build/helper import/network/install occurred.

`check.py` is a stdlib, read-only structural and integrity check. It reads only listed retained metadata pins and authored data. It verifies selected-query completeness against the three parent metadata documents, exact source records/locators, grouping, package/helper projections, caps and unknown-preserving claims; synthetic false-promotion controls must fail. It does not run an inherited builder, provider, source model, decoder, original or comparator. `author-check.json` records its one author execution. `final-locator-check.json` separately verifies all 22 package pointers against the three selected inventory documents after normalizing list-root JSON pointers; final conservative retained-document reads are 3,721,476 bytes, below 4 MiB. Root owns sealing, independent review, shared routing and adoption; no owner, case, release, normative clause or grade changes are proposed.
