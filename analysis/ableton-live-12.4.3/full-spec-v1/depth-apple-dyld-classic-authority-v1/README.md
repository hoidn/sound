# Apple dyld classic binding authority

This source research answers whether primary Apple implementation supports a separately selected revision of the strict encoded-site method. It does. This packet does not implement that revision, execute a dyld parser, reinterpret a prior stream suffix, patch frozen evidence, acquire an image or establish Electric's runtime loader.

Existing retained sources supplied public format declarations and the analyst xexec decoder, but no primary Apple implementation. Official Apple OSS dyld tag `dyld-852.2` resolves through the retained tag response to commit `3f24a36068a96722cf3acbd5087983ce658e9d70`. All seven source files were captured from commit-specific raw URLs under `apple-oss-distributions/dyld`. Receipts retain all nine successful HTTP responses (two tag metadata plus seven source files), URLs, byte counts and SHA-256 identities. This is a pinned published implementation version, not proof that Live 12.4.3 ran this version. The tag object reports an unsigned tag; no signature claim is made.

`selected-functions.txt` losslessly projects the complete relevant functions and narrow type/declaration context: 17 ranges, 1,283 lines and 59,396 source bytes. `selected-source-map.json` gives original file lines and hashes for every range. Full source files retain their license/version context and exact custody; full-file semantic reading is not claimed. No source was compiled or executed. A small owned-data-only checker verifies receipt identities, tag resolution and projections with five negative controls. It does not validate or run Apple's implementation.

The source distinguishes unsigned arithmetic from validity. Classic ordinary/weak bind paths update a `uint64_t` segment offset or `uintptr_t` address using ULEB values. For a 64-bit unsigned state, modular arithmetic follows from the C++ types and operators; that is a language-level inference from source. It does not make every wrapped result a valid binding. Separate emission checks validate segment bounds, symbol/ordinal state, pointer type and permissions. DO_BIND_ADD_ADDR_ULEB invokes the emission handler before advancing state. The legacy loader's address checks and the analyzer's full-width segment checks are not identical, so the proposed analysis must name its selected source path and preserve stricter safety limits.

Lazy and weak formats have separate rules. Whole-stream lazy enumeration starts with POINTER type and zero addend; DONE continues without resetting state. The analyzer rejects lazy type-setting/address-advance/repeat opcodes that ordinary binding accepts; the legacy whole-stream implementation accepts some of those and differs. The single-entry fast lazy path has a distinct restricted parser and supplies POINTER/zero addend to the bind call. No universal reset or opcode acceptance rule is inferred across these paths. Weak enumeration in the analyzer starts with POINTER and WEAK_LOOKUP, disallows ordinal-setting opcodes, and records strong-definition markers separately. The legacy weak updater can actually write coalesced values, conditional on image state and caller-supplied lookup/coalescing results. Encoded weak sites are not proof of an applied runtime replacement.

The bounded recommendation is a separately selected data-only extractor revision, using the analyzer's classic ordinary/weak transitions for the two researched address-update forms, explicit uint64 modular state updates, and independent validation of every emitted 8-byte site. Preserve strict ULEB/SLEB/string bounds, mode-specific state/type rules, complete per-stream uncertainty and no provider resolution. Arithmetic run handling must remain bounded; do not turn every checked operation into a wrap or expand arbitrary repeat counts. The old strict result remains a valid historical partial result. Root must select any new extractor; none is implemented or run here.

No current runtime pointer, provider, class, constructor, ABI, public binding, required-unit closure, behavior grade or main-Live indirect site follows. No shared wiki or prior frozen packet was edited. Root is the sole independent reviewer of this new source/method packet.
