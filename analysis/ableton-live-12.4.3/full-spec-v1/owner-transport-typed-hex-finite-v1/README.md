# Transport R6 finite typed hash-word adoption

This packet adds finite converter expectations to `wiki/specs/transport-state.md`
under design revision 12. Root reviews the added owner wording and mechanical
mapping. The actual observations already have one independent approved review;
this packet neither repeats that review nor runs original code.

The owner remains an analysis-side draft. No handoff or neutral fixture is
published here. Root owns shared routing, coverage and log updates.

## Authority and scope

`case-catalog.json` pins the actual batch manifest, input and result documents,
historical input provenance, and the approved actual review. Its 316 records
retain every selected lexical input: 313 new cases TS-038–TS-350 and three exact
historical supporting controls. There are 158 width/word pairs and eight groups.
These are distinct units, not 316 behavior grades or a new product denominator.

Each record keeps the exact ASCII bytes, width, type ID, input layout, expected
typed word, selected little-endian argument bytes, full captured unsigned integer
and immutable JSON pointers. No host floating-value decoding occurs. The
all-ones-exponent class includes both signs, zero fraction, every one-hot fraction
and all-one fraction, with each input in upper- and lowercase hex. “Quiet” and
“signaling” bit-layout terminology does not provide an FP exception-state result.

All captured words agree with the existing REQ-004/005 hash-bit oracle. Their
admission does not repair a model or general rule. The original setter bodies
were skipped by the four existing GDB void-return stubs: these are argument
observations, not setter-body execution, real node storage, Transport field range
admission, public opening/saving, formatter behavior or Apple/arm64 observations.
The owner does not prescribe the experimental type IDs or stub API to a candidate.

## Checks and inherited limits

Run the inspected, data-only checker with:

```sh
python3 -I -B analysis/ableton-live-12.4.3/full-spec-v1/owner-transport-typed-hex-finite-v1/check.py
```

The checker hashes only the selected retained documents and current canonical
owner; it reconstructs R5, checks body/row preservation and joins the adopted
fields to the already approved input/result records. It does not read raw GDB
outputs, runtime images, provider binaries, original source indices or code, and
does not import or execute an old helper, collector, model or original. Fifteen
negative controls cover lost cases, promoted controls, altered width/case/bits,
erased raw sign extension, invented public/FP/ARM/candidate outcomes, wrong group
aliases, altered review pins, changed legacy U/rounding text and fabricated pins.
The stdout result is retained as `check-results.json`.

The eight 80-byte index-cache warnings, HOME omission, after-only libthread_db
identity, counted-import limitations, grouped retrospective error detection and
ordinary-close/hash without explicit fsync remain qualified by the actual review.
Its timeout cleanup was not exercised; escaped descendants and uncatchable outer
failure/durability coverage are unproved. This adoption adds no execution proof.

The canonical identity in the manifest is an exact R6 review cut, not a permanent
gate on later owner revisions. Batch historical mutable-source pins remain
historical; they are not asserted to equal this newly adopted owner. The only
requested approval is the added owner wording/preservation/mapping scope.
