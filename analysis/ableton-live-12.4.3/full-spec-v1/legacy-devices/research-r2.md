native profiles in the [inventory](full-live-coverage-inventory.md#legacy-native-devices-8).

[execution plan](full-live-specification-plan.md) and [schema](../schema.md) govern
scope and evidence. No profile is complete, released or compatibility-tested.

Erosion2/Redux2 to [distortion](../specs/distortion-devices.md). Modern successors’
controls, transfer laws and saved classes are not assigned to these profiles.
The draft links shared rack, automation, mix and document ownership; those owners
supply no missing legacy DSP or lifecycle result.

## Distinctions that constrain the draft

Observed in D11 auto-filter:B029: pre-9.5 Sets are described as retaining older
filter models and an Upgrade action in the predecessor. The 12.4.3 inventory’s
Auto Filter Legacy profile uses AutoFilter, distinct from AutoFilter2. Its one
exemplar has LegacyMode=false. **Inference:** this suggests two separate naming
levels: the retained AutoFilter profile versus its older filter submode. The
field is not proof of target GUI mode, filter response or upgrade semantics.
The draft keeps the historical upgrade text predecessor-only and target-U.

Observed in D11 auto-filter:B017–B019: external audio can trigger its envelope
without becoming audible donor input. That gives a specific predecessor probe
question, not a target sidechain protocol or a sidechain interface for Auto
Pan, Chorus, Erosion, Flanger, Frequency Shifter, Phaser or Redux.

Observed in D11 chorus:B002, flanger:B003, frequency-shifter:B003 and phaser:B003:
older devices are described as superseded by expanded successors and retained
when opening earlier Sets. Their historical Core Library/User Library claims
cannot determine 12.4.3 browser availability: this retained package actually
contains the named Legacy subtree exemplars. No claim of a target contradiction
or automatic conversion follows from documentation with a different version.

Observed in D12 migration context, HTML line 1144: pre-12.4 Erosion Sets are
described as loading Erosion Legacy. The retained
[migration block](../../analysis/ableton-live-12.4.3/full-spec-v1/legacy-devices/manual-12-erosion-migration-blocks.json)
pins that statement against reused D12 HTML SHA-256
`9cb15cb3d80bda4771e5add2c2b74f5c57d73ee8850e198acf7cf8a51dfd1299`.
Its canonical documentary clause is
[REQ-DST-EROSION-005](../specs/distortion-devices.md#req-dst-erosion-005--legacy-loading-boundary).
It does not specify the Erosion Legacy carrier algorithm, old-state rewriting,
upgrade action, exact target loading or Live 11 parity. The D12 original capture
catalog is pinned to retain source identity instead of creating another capture.

Observed in D11 frequency-shifter:B005–B006: the source’s additive-Hz and Ring
examples name particular frequencies. They are useful predecessor explanations;
no target spectral tolerance, negative-frequency handling, sideband amplitude,
aliasing behavior or equivalence to modern Shifter is established.

Observed in D11 redux-legacy:B004–B009: Downsample factor examples, Soft/Hard,
bit levels and overload LED are documented. The factor-1 no-change description
is scoped to downsampling; it cannot prove whole-device identity with active
bit reduction. No quantizer scaling, zero tie, rounding, interpolation kernel,
LED calibration/hold or CPU savings criterion is established for the target.
Similarly, Auto Filter self-oscillation and Flanger quality adjectives supply
no finite numerical tail, spectral or performance acceptance metric.
