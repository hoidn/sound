# Sets, projects and media-reference workflow evidence

The [project/media draft](../specs/project-media-workflows.md) owns the selected
user-facing lifecycle. Existing [Set structure](live-set-structure.md),
[container](document-container-native.md) and [browser index](browser-index-static.md)
research retain their narrower native/storage ownership. Neither a valid Set
schema nor a native command name proves a save/merge/collect transaction.

Captured Ableton's official
[Managing Files and Sets chapter](https://www.ableton.com/en/live-manual/12/managing-files-and-sets/)
on 2026-10-19, retaining exact HTML, normalized text, URL/UTC/hash metadata and
[manifest](../../analysis/ableton-live-12.4.3/full-spec-v1/project-media/manifest.json).
The page names Version 12 without an exact patch. Every new documentary clause
therefore remains exact-build U. Only source text was inspected; no image,
codec, application, original function or candidate was executed.

This packet distinguishes Set saving from dependency collection, project-local
unused status from cross-project safety, manual reassignment from original-file
identity, and generic Undo History presentation from edit-specific transactions.
The draft has 22 requirements and 34 authored scenarios. It retains missing
search, remapping, file-collision, failure, cancel, undo and teardown outcomes as
unknown. Even the documented Ask/Cancel operation gives no disk atomicity proof.
Audio/video/MIDI export, decoding/cache/ASD and detailed media algorithms remain
uncovered by this packet rather than implicitly specified by its chapter citation.
