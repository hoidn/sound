# ADR 0006: Reference observation reopened; the host is the open prerequisite

## Decision and authority

Adopted by user direction on 2026-10-21. The frozen route census of 2026-10-21
classed 691 required units X, 1,076 S and 3,857 without any evidence route
across 5,624 units, so under [ADR 0003](adr-0003-no-reference-execution.md)
and the [ADR 0005 completion rule](adr-0005-full-live-specification-coverage.md#completion-rule-confirmation--2026-10-20)
about two thirds of the required behavior could never gain evidence and the
whole-product gate could never close. Told that the measure would plateau near
a third unless that decision was reopened, the user directed: "reopen that
decision".

This record reopens ADR 0003's whole-application restriction only. ADR 0003's
extracted-execution rules (label X, slice binding, arm64 inference, recorded
stubs) stay in force. The ADR 0005 completion rule is unchanged: a required
unit without evidence stays unknown and keeps closure open.

## What is reopened

- Observation of the pinned Live 12.4.3 build running as a whole application is
  again an authorized evidence route, labelled **O (observed)**, distinct from
  D (documentary), S (static) and X (extracted execution). It runs under
  [ADR 0002](adr-0002-static-first-analysis.md#runtime-escalation-rule)'s
  escalation record (question, existing evidence, reason, minimal inputs,
  discriminating observation, stopping condition), batched per sitting as the
  design's observation packet.
- Route class **O** joins X, S and none in the family route ledgers. A required
  unit with no X or S route is classed O-pending until an observation packet
  records it; it remains U until then.
- The retained [Phase 4 reference observation batch](../research/phase4-probe-batch.md)
  is reinstated as the first observation run sheet at its retained hashes; later
  records are added by revision, never by editing the retained batch.
- Released payloads keep their "comparison not-run" obligations as recorded, but
  those obligations are no longer permanent: a later release revision may carry
  O expectations or original-versus-candidate results. Released payloads are not
  rewritten.

## Open prerequisite: a reference host

No host exists today. ADR 0003 recorded "mac observation not possible", and the
macOS 15.2 arm64 host that produced the retained captures has no route from this
workstation. Observation under this decision requires a recorded host: machine
identity, OS build, Live build hash against the pinned source, account
isolation and authorization method, and the evidence copy route to this
workstation. Choosing the host is a separate user decision, tracked as plan
D-07. The options, with a recommendation:

1. **Apple-silicon macOS host with Live 12.4.3 installed and authorized**
   (recommended). It observes the arm64 release slice directly, the Phase 4
   run sheet was written for it, and its pre-sitting decisions are already
   listed there.
2. **Intel macOS host.** Observes the x86_64 slice as a whole application;
   arm64 equivalence stays an inference, as for X.
3. **arm64 emulation or macOS virtualization on this workstation.** Not
   recommended: macOS virtualization is licensed only on Apple hardware, no
   emulator is installed, ADR 0003 names an emulator as needing separate
   approval, and it would be new tooling under AGENTS.md.
4. **Compatibility layer for the x86_64 slice on Linux.** Not recommended:
   ADR 0003 refused a compatibility layer, its fidelity for an audio
   application is unproven, and observed values would bind to the layer rather
   than to macOS.

Until D-07 is recorded, no observation is selectable and the plan's selection
order is unchanged.

Note, 2026-10-21: after asking whether observation is possible on this Linux
host, the user removed AGENTS.md's clause against installing tooling. Options 3
and 4 are therefore no longer blocked by that clause; their "not recommended"
stands on technical and licence grounds only. Measured on this host the same
day: the CPU exposes virtualization on all 32 cores, but no KVM device or module
is active, no QEMU, Wine or Darling is installed, and the root filesystem has
4.1 GiB free. ADR 0003's sentence that an arm64 emulator needs separate approval
is ADR 0003's own rule and is answered by D-07 when a host is chosen.

## Consequences

- **Evidence.** An O result carries exact scenario, inputs, procedure, host and
  Live build identity and raw capture hashes. Raw captures stay analyst-only.
  Nothing labelled S or X is relabelled O, and an O result never replaces a
  retained S or X result; disagreements are recorded as open questions.
- **Specs.** Clauses and cases that cite ADR 0003 as the reason they stay
  unknown now cite an O-pending route. This decision grades nothing.
- **Verification.** The [verification index](../verification/index.md)
  completion rule can be met again once a host exists; its evidence-type
  requirement is unchanged.
- **Clean room.** Unchanged under [ADR 0001](adr-0001-documentation.md) and
  AGENTS.md. Observation is analyst-side; implementers see released handoffs only.
- **Tooling.** This decision installs nothing. The host and any tool it needs
  are recorded when provisioned.
- **ADR 0005 confirmation.** Its sentence that the confirmation "authorizes no
  new host/emulator" is superseded as to the host by this decision; the
  completion rule it confirms stands.
