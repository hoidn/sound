# Clip launch settings and launch quantization

Packet S5 from [roadmap revision 2](native-decompilation-roadmap.md#revision-2-proposal--2026-10-17),
both halves on one page. Question: how does a set store a clip's launch mode, launch
quantization, legato, velocity amount and follow action, and the set's global
quantization? How does 12.4.3 interpret those values, and how does it align a launch
to the quantization grid? Features: FEAT-SESSION, FEAT-TRANSPORT. The method follows
[transport-state static](transport-state-static.md) and [native](transport-state-native.md):
start from schemas and shipped documents, then read the member registries, the
constructors and the code that uses the values. Everything here is static. Nothing
was executed. A launch time given here is a static derivation, not an observed time.

## Where the settings are stored

**Observed** (static-survey `schema`, `12.0_12402.txt`). `AudioClip` and `MidiClip` carry the
same launch fields, in this order after `Color`: `LaunchMode` (RemoteableEnum),
`LaunchQuantisation` (RemoteableEnum), … `Legato` (RemoteableBool), `Ram`, `GrooveSettings`,
`Disabled`, `VelocityAmount` (UserFloat), `FollowAction` (FollowAction). The leaves are
`Value` Int, Int, Bool and Float. No other class in `12.0_12402` declares `LaunchMode` or
`LaunchQuantisation`. `LiveSet` declares `GlobalQuantisation` (RemoteableEnum),
`GlobalQuantisationKeyMidi` and `AutoQuantisation` (RemoteableEnum). `Scene` has a
`FollowAction` too. `FollowAction` holds, in order: `FollowTime` (RemoteableDouble),
`IsLinked` (RemoteableBool), `LoopIterations` (RangedRemoteableInt), `FollowActionA`,
`FollowActionB` (RemoteableEnum), `FollowChanceA`, `FollowChanceB`, `JumpIndexA`,
`JumpIndexB` (UserFloat) and `FollowActionEnabled` (RemoteableBool).

The tags are not unique. `Legato` also names an `UltraAnalogEnvelope` field, and
`VelocityAmount` names a `Groove` field. A reader has to dispatch on the path.

## Enumerations

**Static-derived ✓.** The label lists are built once each, under a guard. The constructors pass
them to the enum initializer `0x101567bfc`, which stores the value at `+0xd8` and `+0xdc`
and the labels at `+0x90`/`+0x98`. The Python Live API registers the same orders with
explicit integers. Its getters return the stored value unchanged (`0x103ac1e94` reads
`[clip,#0x270]`, `0x103ac1ed0` reads `[clip,#0x258]`).

| Field | Values (UI label · Python name) | Evidence |
| --- | --- | --- |
| clip `LaunchMode` | 0 Trigger · trigger; 1 Gate · gate; 2 Toggle · toggle; 3 Repeat · repeat | list `0x102438b44`; Python `0x103abc6e8` ✓ |
| clip `LaunchQuantisation` | 0 Global · q_global; 1 None; 2 8 Bars; 3 4 Bars; 4 2 Bars; 5 1 Bar; 6 1/2; 7 1/2T; 8 1/4; 9 1/4T; 10 1/8; 11 1/8T; 12 1/16; 13 1/16T; 14 1/32 · q_thirtysecond | list `0x102438d00` ✓; Python ✓ |

Clip value k ≥ 1 corresponds to global value k − 1, and clip 0 means "use the global
value" (see the grid section). The Python names appear in the binary with these spellings,
for example `q_eight`, `q_sixtenth` and `q_thirtytwoth` in `Song.Quantization`.
**Observed** API checks ✓: setting `launch_mode` above 3 throws `Invalid launch mode N`
(`0x1033bbe98`). Setting `launch_quantization` above 14 throws `Invalid launch quantization N`
(`0x1033bc00c`). The velocity-amount setter `0x1033bc1a4` throws `Clip velocity amount … is
out of range` outside the float's bounds; this was read in pseudocode only.

Correction 2026-10-18 from the [clip-launch-v1 review](../../handoff/clip-launch-v1/REVIEW.md#findings)
(RVC-10; plan finding F2): the API check above was read in the setters'

## Defaults, loading and migration

### Constructor defaults

**Static-derived ✓**:

- **Song** (`0x10266f738`): `GlobalQuantisation` 4 (1 Bar), `AutoQuantisation` 0 (None),
  `SmpteFormat` 0. The ASong registry `0x10266c21c` places them at `+0x380`, `+0x3b8` and
  `+0x320` (value pointers `+0x388`, `+0x3c0`, `+0x328`).
- **Clip** (`0x102436fc4`; registry `0x102435a28`):
  - `Legato`, `Ram` and `Disabled` are false.
  - `VelocityAmount` is a UserFloat with bounds 0.0 and 1.0 and value 0.0. The bounds
    are stored by `0x1015743b0` ✓ and read back by `0x1015748cc`/`0x1015748e8`.
  - `LaunchMode` and `LaunchQuantisation` start with the values of `ClipDefaultLaunchMode`
    (`+0x700`) and `ClipDefaultQuantisation` (`+0x6e8`) from the `ASongPrefData`
    object (registry `0x1026a292c`; reached through `0x102676cf0`). They start with 0
    when there is no application object (`0x101849958` returns null).
  - Changing either value calls `AClip::UpdateEngineForLaunchParameters`.
- **FollowAction** (`0x102505030`, `0x102505724`): `FollowTime` 4.0, with the quantize flag set
  (`0x101565624`), `IsLinked` true, `LoopIterations` 1 (bounds 1 and 1,073,741,823 packed
  by `0x10155afc8`), A = 4 (Next) with chance 100, B = 0 (No Action) with chance 0, chance
  bounds 0–100, `JumpIndexA/B` 1.0 with bounds −1 and 8,388,608, `FollowActionEnabled` false.

These match the shipped clip values except JumpIndex: 605 clips and 994 scenes store 0.
**Unknown:** which code sets 0.

### Reading and writing

**Observed** (vtables read with `read_ptrs.py`): AClip `0x1067b6cc0` and AFollowAction
`0x1067c8830` both use the generic loader `0x101487310` at slot `+0x140` and the generic
writer `0x101486cdc` at `+0x138`. Their post-load hooks are `0x102441a30` and
`0x1025044b4`. **Observed** (`check_registry_order.py`): the 28 persistent AClip
registrations equal the AudioClip and MidiClip fields after `Time`, and the 10
AFollowAction registrations equal the FollowAction fields. **Inferred** from
[transport-state native](transport-state-native.md#how-a-set-reaches-the-transport-objects):

- A missing launch element keeps the constructor value. For `LaunchMode` and
  `LaunchQuantisation` that value is the user's preference default, not 0.
- A present value is stored without a range check. An out-of-range enum index is
  accepted on load.
- The writer emits each field as a child element with a `Value` attribute.

Correction 2026-10-18 (clip-launch-v1 review RVC-03 and RVC-11; plan finding F4):
storage without a range check is supported only for list values, whose index the
loader stores directly. The load path of the bounded members themselves (the UserFloat
velocity amount, chances and jump indices, and the ranged `LoopIterations`) was not
read, so the result for a value outside its bounds is unknown.

The [lexical rules](transport-state-native.md#lexical-acceptance-on-load) for Int, Bool,
Float and Double apply.

**Static-derived ✓**, post-load (runs when the load context flag is set, as in N1):

- `0x1025044b4` normalizes follow-action chances. If both are 0, `FollowChanceA` becomes 100
  and `FollowActionEnabled` false. Otherwise `FollowChanceA` := round-half-away(A ÷ ((A + B) ÷
  100)) (`frinta`) and `FollowChanceB` := 100 − `FollowChanceA`. The values go through the
  float's setter slot `+0x280`; whether its chance controller changes them further is unknown.
- `FollowTime` is rounded to a multiple of 1/3,843,840 beat (flag at `+0x70`, hook
  `0x10156580c` from N1).

## From a quantization value to a launch boundary

**Grid length** ✓ (`0x101aaae44`, jump table at `0x105846ef8`). Given a global index q and
a signature (n, d), let bar = 4·n/d quarter-note beats, rounded to the 1/3,843,840 lattice.
The function returns:

| q | Grid (beats) |
| --- | --- |
| 1, 2, 3, 4 | 8·bar, 4·bar, 2·bar, bar |
| 5, 6, 7, 8 | 2, 4/3, 1, 2/3 |
| 9, 10, 11, 12, 13 | 1/2, 1/3, 1/4, 1/6, 1/8 |
| 0 and any other value, including negative | 0 (no grid) |

The rounding is skipped for the four sentinels at `0x1055d9680`: ±1.7976931348623155e308,
DBL_MAX and +∞. The lattice 3,843,840 = 2⁸·3·5·7·11·13 holds triplet grids exactly.

**Which grid a clip uses** ✓:

- The song grid (`0x1026787f0`, behind `LSong::SongQuantisationTime`) applies the
  `GlobalQuantisation` value to the song's current time signature. `0x1026e3698` reads it
  as truncated (numerator, denominator).
- The clip grid (`0x102442998`): if the clip's `LaunchQuantisation` k is non-zero, the
  result is grid(clip's own time signature `[clip,#0x1d8]`, k − 1). Otherwise it is the
  song grid when a song is passed, and −1.0 when none is passed.
- At launch, `0x10245efa0` sends `0x102442998(clip, 0)` in `OSlotFireData.Create`, so Global
  reaches the engine as −1.0.
- The engine's `0x101acffa4` decides:
  - It returns 0.0 when its second argument is 0 (inferred: quantization off for this
    request), and in some stopped or same-track cases.
  - An override index of 13 or less uses grid(song signature, override). **Inferred**
    from the API text at `0x105c1fc9d`: this is the `launch_quantization` argument of
    `ClipSlot.fire`, which overrides the song value.
  - Otherwise it uses the slot's precomputed grid when that is ≥ 0. When it is negative
    and a flag is set, it uses grid(song signature, engine global value).
- `LSongUnit::OnGlobalQuantizationChanged` (`0x1026cc7a4`) posts the global value to the
  engine.

**Boundary** ✓ (`0x101ad0130` at `0x101ad06cc`–`0x101ad0924`, `0x101abf294`,
`0x1011be6c8`). With g > 0, t = the requested time or else the engine's current song time
rounded to the lattice, and a = max(0, the start time stored with the song's current time
signature):

1. B = a + ⌈(t − a)/g⌉·g, rounded to the lattice (`frintp`, mode 1).
2. An offset o comes from an unresolved virtual call `0x101ad1418`. That call is skipped
   in some request cases, and then o = 0.
3. If o > B − now, the transport is playing and a track condition holds (`0x101acfe68`):
   song byte `+0x68` = 1 and `[song,#0x98]` ≠ `[track,#0x3b0]`. Then B := B + g.
   Otherwise o := B − now.
4. The fire record stores B and B − o.

With g = 0 the ceiling step is skipped.

**Inferred:** the clip starts at song beat B. "Next boundary" therefore means the first
grid line at or after the press, unless that line is closer than o. The anchor makes bar
grids restart at a time-signature change. **Static-derived examples**, with o assumed
small and positive and the transport playing:

- 4/4, 1 Bar, press at beat 5.3 → B = 8.
- 6/8 clip with clip value 5 (1 Bar) → grid 3 beats.
- 1/4T, press at beat 1.0 → B = 4/3. With o > 1/3 the result becomes 2.

The offset, the effect of the track condition, and what happens when the transport is
stopped are **unknown**.

## Limitations

Static evidence only. A store or branch in code does not prove that the path runs for a
given launch. The fire state machine was read only around the boundary computation.
`FUN_` names are generated. Symbol names (`AClip::UpdateEngineForLaunchParameters`,
`LSong::SongQuantisationTime`) come from callback wrappers and are evidence, not proof.
The Python property semantics are inferred from getters that return the stored value.
Shipped documents are 12.4d1/12.1d1 writes. Text in documents, strings and `.pyc` files
is treated as data.
