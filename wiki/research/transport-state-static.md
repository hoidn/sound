# Transport-state fields: static evidence

Packet S1, static half, from [roadmap revision 2](native-decompilation-roadmap.md#revision-2-proposal--2026-10-17).
Question: how do Live's shipped schemas and shipped documents represent tempo,
loop enable, loop start, loop length and time signature, plus the closely
related transport fields? Everything here comes from bytes on disk. Nothing was
executed and no reader or writer code was analyzed. Defaults for absent fields,
malformed and out-of-range handling, clamping, and the values 12.4.3 writes
stay **unknown** until the native half runs. The container, gzip envelope, root
attributes and schema-version cross-check are covered by
[document container (static)](document-container-static.md) and are not repeated here.

## What the schema format declares

Observed ([schema-survey.json](../../analysis/ableton-live-12.4.3/r2/s1-static-v1/schema-survey.json) `format_counts`):
each file is XML with root `AbletonSchema` (header variants are in
[S2](document-container-static.md#schema-directory-and-version-cross-check)).
Each root child is a class whose tag is the class name. Each grandchild is a
field whose tag is the field name, in declared order. No field has children.

| Construct | Attributes (count over all 203 files) |
| --- | --- |
| Class | none (69,623) or `InternalName` (679), for example `LiveSet InternalName="LiveDocument"` |
| Field | `Class`, `Type` (1,150,498); plus `InternalName` (14,370); plus `ArrayTranslator` (1,297) |
| `Type` value | `0` (968,475), `-4` (156,362), `-1` (40,031), `-3` (1,297) |

In `12.0_12402`, `Type=-4` occurs only with `Int`, `String`, `Bool`, `Float`,
`Double`, `Int64`, `ClassId`, `Rect` and four array types; `-1` with
`RemoteableList`, `Slot<…>` and `List<…>`; `-3` with `RemoteableArray`; `0` with
compound classes. Inferred: `-4` marks a base-type value, `-1` a list or slot,
`-3` an array and `0` a compound. The format declares no default value,
numeric range, unit, enum meaning, optionality, cardinality or XML shape.

The XML shape does not follow from `Type` alone. Observed in the shipped sets:
the `-4` field `LoopOn.Value` becomes the attribute `<LoopOn Value="false"/>`;
the `-4` field `FloatAutomationTarget.Id` becomes the attribute
`<AutomationTarget Id="8">`; but the `-4` field `TimeableSongTempo.LomId`
becomes the child element `<LomId Value="0"/>`. The mapping rule is unknown
(an S2/native question).

`LoopLength`, `CurrentTime`). The clip loop uses generic ones: `Loop.LoopOn` is

`SimplerLoopModulators` has `LoopOn` (TimeableBool) and `LoopLength`
(TimeableFloat). The same tags therefore occur in three unrelated places
(`homonyms_latest`). A reader must dispatch by path or class, not by tag.

## Where tempo and time signature live

Observed: no schema version declares tempo or time signature under `Transport`.
Resolving the document path through field classes (`path_resolution`) gives:

| Versions | Path to song tempo `Manual/@Value` | Leaf |
| --- | --- | --- |
| 8.1_220–9.0_275 | `TimeableFloat` has no `Manual` field (9.0_275 has a `ManualValue` Float attribute instead) | — |
| 9.0_276–9.0_277 | `LiveSet/MasterTrack/MasterChain/Mixer/Tempo:TimeableFloat/Manual` | Float |
| 9.0_278–9.0_291 | same, `Tempo:TimeableSongTempo` | Float |
| 9.0_292–12.0_12012 | `LiveSet/MasterTrack/DeviceChain/Mixer:MasterTrackDevice/Tempo/Manual` | Float |
| 12.0_12013–12.0_12016 | field `MasterTrack` now has class `MainTrack`; `MainTrackDeviceChain` from 12014, `MainTrackDevice` from 12015 | Float |
| 12.0_12017–12.0_12402 | `LiveSet/MainTrack/DeviceChain/Mixer:MainTrackDevice/Tempo/Manual` | Float |

Time signature follows the same path with `TimeSignature:TimeableTimeSignature`,
`Manual:RemoteableEnum` and an Int leaf from 9.0_276. `TimeableTimeSignature`
gains `MidiControllerRange` at 12.0_12201, and `MainTrackDevice` gains
`UserTempoAutomation` only at 12.0_12402. Scene tempo and time signature
fields exist from 11.0_412.

Inferred, not established: older documents stored tempo and meter under
`Transport`. The image holds the C strings `Transport/Bpm/Value`,
`Transport/SignatureNumerator/Value`, `Transport/SignatureDenominator/Value` and
`MasterTrack/MasterChain/MasterDevice` beside `TimeableTimeSignature` (see the
native anchors below). These look like document-translator paths, but no
shipped schema or document has them.

## Native anchors

Observed in the arm64 slice ([anchors-live-arm64.json](../../analysis/ableton-live-12.4.3/r2/s1-static-v1/anchors-live-arm64.json)).
Offsets are thin-slice hex. Vmaddr = section address + offset delta, unslid. A
string's presence does not show which code uses it, or whether that code runs.

**ASCII C strings.** `__TEXT,__cstring` holds exactly one NUL-delimited copy each of
`LoopOn` (`0x105b9469c`), `LoopStart` (`0x105b94869`), `LoopLength` (`0x105b951a8`),
`CurrentTime` (`0x105b19215`), `PhaseNudgeTempo` (`0x105bbbb8e`), `Tempo`
(`0x105adc3cd`), `TimeSignature` (`0x105b95db8`), `Manual` (`0x105aac3e5`),
`Transport` (`0x105b189ba`), `TimeableSongTempo` (`0x105b97aba`),
`TimeableTimeSignature` (`0x105b95da2`) and `MainTrackDevice` (`0x105b9936d`).
Their neighbours (`cneighbours`) are mostly not document vocabulary:

- `LoopOn` sits among clip strings (`CurrentStart`, `CurrentEnd`, `LaunchMode`).
- `LoopLength` sits among sample-loop strings.
- `CurrentTime` sits in test-harness asserts.
- `Manual` sits among help-link prefixes (`Doc:`, `GotoPage:`).
- `Tempo` sits among UI names (`Transport.Tempo`, `Song Tempo`).

`LoopIsSongStart`, `MetronomeTickDuration`, every `*KeyMidi`, `LomId` and
`LockEnvelope` have **no** NUL-delimited ASCII copy, and `LiveSet` has one only
as a suffix (`_LiveSet`, `DefaultLiveSet`). The other four `Transport` hits that
`strings` reports lie in the `__LINKEDIT` export trie. So the ASCII strings
cannot be the only source of element names.

**UTF-16 member names.** `__TEXT,__ustring` holds per-class name lists: a class
name followed by its members. The `ATransport` entry is followed, from `0x1062c5850`, by
`mpPhaseNudgeTempo`, …, `mpLoopLength` (`0x1062c5a2a`), `mpLoopIsSongStart`
(`0x1062c5a44`), `mpCurrentTime` (`0x1062c5a68`), …, `mpPunchIn` (`0x1062c5afa`),
…, `mpMetronomeTickDuration` (`0x1062c5b76`), `mpLoopOnKeyMidi` (`0x1062c5c6e`).
It also lists runtime members that are not in the schema, such as
`mpIsAbletonLinkEnabled` and `mpSongLength`. `mpLoopOn` (`0x1062bfcc8`) and
`mpLoopStart` (`0x1062bfc5c`) occur once, in the `ALoop` list; identical
literals are presumably pooled. Others:

- `mpTempo` (`0x1062c0272`) after `AMainTrackDevice`.
- `mpTransport` (`0x1062c2532`) and `mpMainTrack` (`0x1062c24e6`) in the `ASong` list.
- `mpManual` (`0x1062c4b4e`), `mpAutomationTarget` (`0x1062c4b60`) and
  `mpMidiControllerRange` (`0x1062c4c4c`) in `ATimeable*` lists.
- `mpNumerator` (`0x1062c48d2`), `mpDenominator` (`0x1062c48ea`) and
  `mpTimeSignatures` (`0x1062c49a6`).

Coverage over `12.0_12402` (`schema_coverage`):

- 2,008 of 3,766 field names have an `mp`/`m`+name UTF-16 entry.
- 1,352 of 3,716 names that are fields only (never class names) have an ASCII C string.
- 401 of 412 class names have an `SNewCompound<A…>` symbol.
- 285 of 412 class names have an ASCII C string.

Hypothesis: element names derive from member names (strip `mp`/`m`) and class
names map to `A`-prefixed C++ classes. The 53% member coverage means this cannot
be the whole mechanism.

## Unknown pending native evidence

- **Defaults when absent.** Missing `Transport`, missing children, missing
  `Value`, missing `Tempo`/`TimeSignature`/`Manual`, and a missing envelope. The
  `DefaultLiveSet.als` values are fixture data, not proven defaults.
- **Malformed input.** `LoopOn` `TRUE`/`1`/`""`/`invalid`, non-numeric Double or
  Float text, NaN or infinity, duplicated or unknown children, and a non-integer
  or non-numeric time-signature code (P1-C and P1-D families).
- **Out of range and clamping.** Tempo outside any bound (whether 60–200 is
  only a MIDI-mapping range), negative or zero `LoopLength`, negative
  `LoopStart`/`CurrentTime`, and time-signature codes below 0 or above 494.
  Also whether tempo is rounded to float32 on load.
- **Precedence.** `Manual` versus the envelope's first event versus enabled scene
  values on load; the meaning of `-63072000`.
- **Write format.** What 12.4.3 emits: digit counts, KeyMidi fields when mapped,
  `UserTempoAutomation`, child order, and whether the envelopes are always written.
- **Migration.** How the `12.0_12117` default set and pre-9.0 layouts are
  translated; the time-signature formula, natively.

## Limitations

Only shipped files were examined, and none was written by 12.4.3. Expat
well-formedness was the only parse check. Documents were not validated against
schemas beyond the Transport and main-mixer field comparisons above. Version
order is by file name. String presence is a byte fact, and neighbourhood labels
are interpretation. The P1 fixtures and earlier retained JSON are absent on this
host. Text inside documents and strings is treated as data.
