# Automation envelopes: storage and evaluation

Packet S6 for FEAT-AUTOMATION. Question: how does a Live document store
automation, and how does Live 12.4.3 evaluate a stored envelope? The static
half reads the shipped schemas and documents. The native half follows the
reader, the defaults, load-time checks and the interpolation code in the arm64
image. Packet S6 is static; the [results of 2026-10-18](#results-2026-10-18-extracted-execution-packet-x2)
add extracted execution of x86_64 functions. "Load fails" means the
traced code throws the corrupt-document error. The user-visible outcome of
that error is the open item shared with the
[container packet](document-container-native.md#how-a-refusal-becomes-an-error).
The page follows the pattern of [transport-state static](transport-state-static.md)
and [transport-state native](transport-state-native.md), which it extends for the
one-event tempo and time-signature envelopes.

## Schema: classes and their history

Observed in all 203 schema files (`segments`, `holder_fields`). Ordering is
(major, minor, translator) from the file name. Translator numbers repeat across
families, so isolated 8.x gaps (for example 8.2_260–8.3_270 lacking
`AutomationTarget`) can be ordering artifacts. Lines are in `12.0_12402.txt`.

| Class (line) | Fields: Class · Type | History |
| --- | --- | --- |
| `AutomationEnvelope` (839) | `EnvelopeTarget`: PtrBase · 0; `Automation`: ListAutomation · 0 | 10.0_367 → 12402, unchanged |
| `AutomationEnvelopes` (843) | `Envelopes`: RemoteableList · -1 | 10.0_367 → 12402; held by AudioTrack, MidiTrack, GroupTrack, ReturnTrack, PreHearTrack, MasterTrack (to 12.0_12012) and MainTrack (from 12.0_12013) |
| `ClipEnvelope` (1220) | `EnvelopeTarget`: PtrBase; `Automation`: ListAutomation; `LoopSlot`: RemoteableSlot; `ScrollerTimePreserver` | 8.1_274 → 12402; held by AudioClip and MidiClip `Envelopes`: ClipEnvelopes |
| `ListAutomation` (3793) | `Events`: RemoteableList · -1; `AutomationTransformViewState` (from 10.0_377) | all 203 |
| `FloatEvent` (2563) | `Time`: Double; `Value`: Float; `CurveControl1X`, `CurveControl1Y`, `CurveControl2X`, `CurveControl2Y`: Double (all -4) | curve fields from 9.0_303 |
| `BoolEvent` (915), `EnumEvent` (2252) | `Time`: Double; `Value`: Bool / Int | all 203 |
| `FloatAutomationTarget`, `BoolAutomationTarget`, `EnumAutomationTarget`, `TimeableModulationTarget`, `UserFloatModulationTarget` | `Id`: Int · -4; `LockEnvelope`: RemoteableEnum · 0 | targets from 8.1_274/9.0_274 |
| `PtrBase` (6268) | `PointeeId`: Int · -4 | all 203 |
| `MidiControllers` | `ControllerTargets.0` … `ControllerTargets.130`: UserFloatModulationTarget | all 203 |

The storage moved at 10.0_367/10.0_369. Before, each `TimeableFloat`, `TimeableBool`,
`TimeableEnum`, `TimeablePlugin*`, `TimeableSongTempo` and `TimeableTimeSignature`
held its own `ArrangerAutomation` (and Float ones a `ModulationAutomation`), last
in 10.0_368. From 10.0_367 each track holds an `AutomationEnvelopes` list whose
envelopes point at a target by Id. `TimeableMidiClip` and `TimeableSample` keep
an `ArrangerAutomation` to 12402. `TakeLane.ClipAutomation` (from 11.0_405) is
also a ListAutomation. `LiveSet.NextPointeeId` (Int) is in 132 versions,
including 12402. In 12402, 139 fields have class UserFloatModulationTarget,
3 FloatAutomationTarget, 3 EnumAutomationTarget, 1 BoolAutomationTarget,
3 TimeableModulationTarget and 9 CollisionModTarget (`latest_target_owner_counts`).

The format declares no value range, unit, curve meaning or ordering rule.

## Native: reading, defaults and load checks

**Observed** in disassembly where marked ✓; otherwise in pseudocode
([notes](../../analysis/ableton-live-12.4.3/r2/s6-automation-v1/notes.md)).

- **Classes and members.** `AFloatEvent` (factory `0x1027782b8`, registry
  `0x1027782ec`) has `mValue` at +0x58 and `mCurveControl1X/1Y/2X/2Y` at
  +0x60…+0x78, all attribute-flagged; `mTime` (+0x50) comes from the event base
  (`0x1024deaf8`). Events load through the generic loader `0x101487310` and are
  written by the generic writer `0x101486cdc` described in
  [transport-state native](transport-state-native.md#how-a-set-reaches-the-transport-objects).
  The parser also accepts `Id` on list items ([N1 notes](../../analysis/ableton-live-12.4.3/r2/n1-transport-state-v1/notes.md)).
- **Defaults** (a missing attribute leaves the constructor value): `Time` DBL_MAX ✓
  (`0x1024deba8`, written `Invalid`), `FloatEvent` `Value` FLT_MAX ✓ and curve controls
  0.5, 0.5, 0.5, 0.5 ✓ (`0x1027785a0`), `BoolEvent` false ✓ (`0x102777adc`),
  `EnumEvent` INT_MIN ✓ (`0x102777f3c`), `PointeeId` 0 (`0x101535bd8`).
- **Load sequence** ✓ (`0x101486fe4`): create the root, run its loader, run the root
  post-load hook when the context asks for it, then walk the whole tree post-order
  (`0x101487198` ✓) calling slot +0x100 on every compound. For `AAutomationEnvelope`
  (`0x1024050d8` ✓) and `AClipEnvelope` (`0x10245194c` ✓) that slot calls the
  automation's check `0x102561a28` ✓:
  - no events → `Automation has no events.` → corrupt-document error;
  - first event time neither −63,072,000 nor 0.0 → `DocumentCorrupt:` log line and
    `First automation event has invalid time.` → corrupt-document error.
  Only the first event is checked. The timeline lists of arrangement clips are not
  envelopes and are not reached by this check.
- **Curve controls on load** ✓ (`0x102778870`, the `AFloatEvent` post-load hook): if the
  cubic Bezier (0, x1, x2, 1) or (0, y1, y2, 1) is not monotone on [0, 1]
  (`0x1012132d8` ✓), all four controls become 0.5. The test rejects non-finite values,
  accepts ordered control values, and otherwise rejects when the derivative has a
  root strictly inside (0, 1). Applied to the shipped curves
  ([curve-check.json](../../analysis/ableton-live-12.4.3/r2/s6-automation-v1/curve-check.json)):
  4,151 / 4,151 kept, including the 7 with a Y control above 1.
- **Curve controls on save** ✓ (`0x102778828`, slot +0x150): a curve control equal to 0.5
  counts as default and the generic writer skips it, one attribute at a time.
  This explains linear events without curve attributes.
- **Target pointer** ✓ (`0x101535e0c`): the pointer is resolved lazily by Id through
  the document. A missing Id logs `Invalid Pointee ID {id} in APtr` and then fails the
  assertion `mpObject` in `APtr.cpp` and calls `abort` (`0x1054147b8` ✓). **Unknown:**
  whether opening a set dereferences every envelope target (process abort) or
  something drops such envelopes first (PRB-S6-02).
- **No sorting found.** `AListAutomation`'s post-load slot is generic, its +0x100 slot
  is a no-op, and its change handler `0x102565f84` only widens a changed-time range.
  The searches assume ascending times. An inserting path that sorts was not ruled out.
- **Legacy translation** (pseudocode, `0x101492afc`; see also
  [transport-state native](transport-state-native.md#what--63072000-is)): in pre-10
  documents the first `ArrangerAutomation` event must be at time 0.0, else
  `Event of unautomated parameter is not at 0.0`. A single event moves to −63,072,000.
  With several events, a copy of the first event's class and value is inserted at
  −63,072,000. This produces the observed lower-bound-equals-next-value invariant.

## Native: evaluation

**Which interpolator.** `vtable_owner.py` attributes the interpolator getter: ATimeableFloat,
ATimeableSongTempo, ATimeablePluginFloat and the modulation targets
(ATimeableModulationTarget, AUserFloatModulationTarget) return the
`TFloatAutomationInterpolator` singleton. ATimeableBool, ATimeableEnum,
ATimeableTimeSignature and ATimeablePluginEnum return `TDiscreteAutomationInterpolator`.

**Locating the segment.** `0x102565a48` finds the last event with time < t (starting
from the nearest of the second event, the last event and a cached event, then
walking). The float search ✓ (`0x102565974`) moves to the next event, the first with
time ≥ t. A mode flag selects the last instead of the first event at a time equal
to t. The discrete search ✓ (`0x102565e10`) returns the event at or before t under the
same mode.

**Float value** ✓ (`0x1024095b4`), at song or clip time t:

1. No event at or after t: the value of the last event (hold).
2. An event at exactly t: that event's value. At a step, the mode decides between
   the two coincident events.
3. Otherwise, with a = previous event and b = next event:
   - a.value = b.value: that value;
   - a carries a non-default curve (`0x1027778a4` ✓: not all four equal 0.5): cubic
     Bezier through P0 = (tₐ, vₐ), P1 = (tₐ + x1·Δt, vₐ + y1·Δv),
     P2 = (tₐ + x2·Δt, vₐ + y2·Δv), P3 = (t_b, v_b) (`0x102403c88`). Live finds
     the parameter s with x(s) = t by bisection from s = 0.5 until |x(s) − t| ≤ 1e−8
     (`0x101212e30` ✓) and returns y(s), clamped to the target range (`0x102404218`);
   - else linear: frac = (t − tₐ)/(t_b − tₐ), v = vₐ − frac·vₐ + frac·v_b in double,
     rounded to float32, then passed through a range remap that is the identity at
     full range (`0x102779088`).
4. No guard was found for t before the first event: the traced path reads a null
   previous event. The lower-bound event at −63,072,000 makes every later time
   have a previous event.

The curve control of a segment sits on its **start** event. **Inferred:** controls
are normalized to the segment's time and value span, which explains X ∈ [0, 1] and
the monotonicity rule.

**Bool and Enum value** ✓ (`0x10240a84c`): no interpolation. The value is that of the
last event at or before t (mode 1) or strictly before t (mode 0).

**Value conversion (partial).** Before the linear step, both values pass through the
converter supplied by the automation's provider (`0x101574bb0`, a virtual call when
a converter object exists). One construction site (`0x10275c5a0`) builds a provider
without a converter object, so values stay in the raw domain. Correction 2026-10-17 from the
[SPEC-AUTOMATION-ENVELOPES](../specs/automation-envelopes.md) draft check: that path does not
clamp; the code shows a clamp only for curved segments, so AE-C12 is unknown.
**Unknown:** the converter used for ordinary track and clip envelopes, so whether
some parameters interpolate in a non-linear domain.

Correction 2026-10-18 from [SPEC-AUTOMATION-ENVELOPES](../specs/automation-envelopes.md)
revision 2 (handoff finding F1): the conversion is not limited to the linear step.
In the disassembly of `0x1024095b4` ✓ the end-of-list, event-time and equal-value
branches also call `0x102778f50` and `0x101574bb0` (calls at `0x10240973c`,
`0x1024097dc` and `0x10240997c`). Every Float value therefore depends on the
converter, which the Float entry `0x1024094c0` requests from the automation's
slot +0x238; steps 1 to 3 give stored values only if it leaves them unchanged. The
Bool and Enum path has no such step. The discrete entry `0x10240a83c` tail-calls
`0x10240a84c` ✓, which requests no converter and returns the selected event's
slot +0x1f0. That slot returns the stored value as a float (`ABoolEvent`
`0x102777cfc`, `AEnumEvent` `0x102778168`). The entry, the slot reads and the two getters come from
scratch corpus and image lookups on 2026-10-18 that are not retained; the spec's
appendix lists them.
