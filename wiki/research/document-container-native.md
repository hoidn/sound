# Document container and version acceptance: native evidence

Packet S2, native half (work packet N2), from [roadmap revision 2](native-decompilation-roadmap.md#revision-2-proposal--2026-10-17).
It continues the [static half](document-container-static.md), which described the
bytes of shipped documents. The question here: what does the 12.4.3 loader
accept and reject at the container and root-element level, and what does the
writer emit? Everything below comes from reading code. Nothing was executed, and
no statement here is a runtime observation. The draft contract is
[SPEC-ALS-CONTAINER](../specs/als-container.md); the newcomer walkthrough is
[document version check](learning/walkthroughs/document-version-check.md).

## Reader entry points and stream detection

Observed (disassembly, [n2-0002 `0x10148389c`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0002/functions/0x10148389c.json)):
the general reader reads two bytes and dispatches. It has 28 direct call sites,
one of them its own gzip recursion ([index-lookups.jsonl](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/index-lookups.jsonl)).

| First bytes | Action |
| --- | --- |
| `1F 8B` | Asks the stream for its file path (vtable `+0x78`). With a path, reopens the file through a gzip stream object (`0x10146208c`) and dispatches again on the decompressed bytes. With none, throws `Can't read a gzip'ed document from a non-file`. |
| `AB 1E` | Legacy binary reader `0x101483d00` |
| `3C 3F` (`<?`) | Seeks back two bytes and runs the XML reader `0x101484108` |
| `FE FF`, `FF FE`, `00 41`, `41 00` | UTF-16 text readers `0x1014845f0` / `0x101484724` |
| `EF BB BF` followed by `Ab`, or `Ab` | Text reader `0x101484858`; the BOM bytes at `0x10581394d` are in [image-probe.json](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/image-probe.json) |
| anything else, or fewer than two bytes | Calls `0x101483cec`, which references `Unknown Compound Stream Type` ([n2-0001](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0001/refs/0x105b914eb.json)) |

The body of `0x101483cec` is not in the kept evidence. Inferred: it raises the
corrupt-document error with that detail, as the second entry does explicitly
through `0x101488e64` (below).

A second entry, `0x10146c0d4` → `0x10146c258` ([n2-0002](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0002/functions/0x10146c258.c),
[n2-0005 `0x10146c0d4`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0005/functions/0x10146c0d4.c)),
recognizes only gzip, `<?` and `AB 1E`. Observed (pseudocode): any other
two-byte prefix returns no document and no error; fewer than two bytes raises
the corrupt-document error with `Unknown Compound Stream Type`; with a nonzero
mode argument it refuses XML (`CompoundTool doesn't support XML documents`).
Before parsing, it stores an expected Creator prefix and a current
(major, minor) pair in the parser (`0x101529908`, `0x101529900`), taken from
app-info accessors `0x1011c4104`, `0x1011c41c4` and `0x1011c41fc`. It has five
direct callers, whose roles were not traced.

Static-derived consequences:

- Neither dispatcher looks at the file name. An `.als` that begins with `<?`
  reaches the XML reader exactly as a decompressed gzip payload does.
- On the general entry an XML document is recognized only by its first two
  bytes `<?`. A UTF-8 BOM, leading whitespace or a missing XML declaration
  leads to `Unknown Compound Stream Type`. On the second entry the same inputs
  produce no document and no error; what its callers then do is unknown.
- Gzip input must come from a file. The gzip stream object was not traced, so
  handling of header flags such as FNAME, multiple members, CRC errors and
  truncation is **unknown**.

Unknown: which entry File > Open uses. `0x1018536d4` logs `Loading document `,
calls the general reader, then logs `Loaded document was created by ` with the
Creator it returns ([n2-0003](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0003/functions/0x1018536d4.c)).
It has one direct caller, `0x1002e6e00`, and data references at seven
addresses between `0x1066d3628` and `0x1068e7bc8`, so it is also reached
through tables. Its use by File > Open is inferred from the log text only.

## Root element and attributes

Observed ([image-probe.json](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/image-probe.json),
[`0x1015286a4`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/corpus/0x1015286a4.c)):
both readers construct a parser whose vtable is at `0x106676ee0`. Slot `+0x40`
(`0x10145f2d0`) runs the parse loop `0x1012475a8`; slot `+0x68` is the error
handler `0x101529970`; slot `+0x70` is the start-element handler `0x1015299e0`.
The image contains `expat_2.6.4` at `0x105c82aa0`. Inferred: the loop drives
Expat, from its buffer calls and its test for error code 35 (`XML_ERROR_ABORTED`).

Observed (disassembly `0x101529c5c`–`0x101529d2c` and pseudocode,
[n2-0002 `0x1015299e0`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0002/functions/0x1015299e0.json)):

- The root name must be exactly the 7 bytes `Ableton`. The comparison is
  case-sensitive. Otherwise the handler throws
  `Expected 'Ableton' root node, got '$1' instead` with the name found.
- It then reads attributes by exact, case-sensitive name (strlen plus memcmp in
  `0x10152a900` for integers and `0x10152ab04` for strings): `MajorVersion`
  into parser `+0xbc`, `MinorVersion` into `+0xc0`. If the header-only flag
  `+0xb8` is set it stops the parse here. Otherwise it reads
  `SchemaChangeCount` into `+0x40` and `Creator` into `+0x48`.
- Attribute order does not matter, and no other attribute is examined.
  `Revision` is never read: the only function referring to that string is the
  writer ([n2-0001](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0001/refs/0x105b91713.json)).
- A missing string attribute takes the shared empty string from `0x1011cb734`.

Integer attributes (disassembly, [n2-0003 `0x10152a900`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0003/functions/0x10152a900.json)):
a missing attribute yields 0. A present value goes to `0x1002fd908`; if that
does not report success (bit 32 of its result), the handler throws
`Illegal value for int attribute: $1` with the raw value.

The integer parser (disassembly, [n2-0005 `0x1002fd908`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0005/functions/0x1002fd908.json)),
observed:

- It fails on an empty or all-space value.
- It finds the first and last non-space bytes; only `0x20` counts as a space.
- It skips one `+` at the start position, and fails if `-` follows that `+`.
- It fails if any byte of the whole value is 0x80 or above.
- It fails if the substring it would convert is longer than 63 bytes.
- It passes a substring to `0x1002fda78` and requires the returned end pointer
  to equal the substring end and the error code to be zero.

The substring starts after leading spaces and the `+`. Its length is
`min(length − start, end index after trailing spaces)`. The second term is an
end *index*, not a count. Static derivation: when the value has leading spaces
or a `+` **and** trailing spaces, the substring keeps the trailing spaces. So
` 5`, `+5`, `  +5` and `5 ` reduce to exactly `5`, but ` 5 `, `+5 ` and ` +5 `
reduce to `5 `. The converter `0x1002fda78` is not in the kept evidence.
Inferred: like a standard decimal conversion it stops at the space, so those
three values are rejected as illegal integers. This contradicts the packet's
case expectation for N2-014 (see [corrections](#corrections-to-the-packet-notes-and-cases)).

Observed (pseudocode `0x1015299e0`, call at `0x101529e88`): the version check
does not run at the root. It runs at the first child of the root, after the
class lookup `0x10147fcc0`. An unknown child class sets the
versioned flags `+0xc8` and `+0x61`. A known class copies its own flag at class
`+0xbe` (`0x10147fdbc`). The check `0x101529024` runs only when that flag is set.
Inferred: Live Sets are versioned, because the writer emits these attributes only
for classes with that flag and every shipped set carries them. Which document
kinds skip the check is unknown. A further child of the root throws
`More than one document in one stream` when the document field `+0xa0` is
already set; when that field is set during the first child was not traced.

## Version acceptance

Observed (disassembly `0x101529038`–`0x101529078` and pseudocode,
[n2-0002 `0x101529024`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0002/functions/0x101529024.json)),
in this order:

| Check | Condition | Result |
| --- | --- | --- |
| 1 | MajorVersion is 0 (missing or literal `0`) | Throw `MajorVersion attribute missing from 'Ableton' root node` |
| 2 | MinorVersion string is non-null and its size field (`+4`) masked with `~1` equals 2 | Throw `MinorVersion attribute missing from 'Ableton' root node` |
| 3 | `(MajorVersion & ~1) != 4`, so not 4 or 5 | If MajorVersion ≥ 6, set the newer flag `+0x29`; throw `Unsupported MajorVersion (<n>)` |
| 4 | Schema lookup `0x101514c6c(MinorVersion)` returns null | Store MinorVersion at `+0x38`; throw `Unsupported MinorVersion ($1)` |

Inferred, check 2: the string object keeps its byte size, terminator
included, at `+4`, and its UTF-16 text at `+0x10`. That layout comes from
`0x101429854`, which computes the length as `size/2 − 1`, and from
`0x101432520`, which allocates `2·length + 2` bytes. A size of 2 is the empty
string, so check 2 means "MinorVersion is empty". Whether the shared empty
string used for a *missing* attribute is a non-null size-2 object or a null
pointer is **unknown**. If it is null, check 2 is skipped for a missing
attribute, and check 4 then fails on an empty name instead. Either way the
document is refused; only the detail text differs.

## How a refusal becomes an error

Observed (pseudocode): `0x101247760` formats a detail
`{} (at line {}, column {})` and passes it to handler slot `+0x68`.
`0x101529970` sets parser `+0x28` and stores the detail at `+0x30`. The parse
loop `0x1012475a8` calls this on an Expat error (message from Expat), on an
aborted parse whose deliberate-stop flag is clear (message stored at `+0x50`),
and on out-of-memory or I/O failure.

Inferred: an exception thrown by the start-element handler is caught at the
Expat callback boundary, stored as the `+0x50` message and the parse aborted.
That catch site is not in the kept evidence. The design supports it, because the
handler sets `+0x29`, `+0x38` and `+0x60` immediately before throwing, and only
the post-parse function reads those flags.

Observed (disassembly `0x1015289c8`–`0x101528af0`,
[n2-0003 `0x1015289c8`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0003/functions/0x1015289c8.json)):
after the parse, `0x1015289c8` decides in this order. Its only callers are
the two readers.

| Step | Condition | Outcome |
| --- | --- | --- |
| 1 | Newer flag `+0x29` | Newer-version error via `0x101528c84` |
| 2 | `+0x38` holds a non-empty MinorVersion that `0x101514e30` parses as `<a>.<b>_<c>` | a > `[+0x58]` (signed), or a = `[+0x58]` and b > `[+0x5c]`: specific newer-version error. Otherwise, if the schema-directory scan `0x101514f7c` finds family a.b and its largest translator < c: newer-version error via `0x101528c84` |
| 3 | Flag `+0x60` (below) | Newer-version error via `0x101528c84` |
| 4 | Error flag `+0x28` | Corrupt-document error `0x10148229c(document, detail)` |
| 5 | No document at `+0xa0` | Corrupt-document error with `No document found` |
| 6 | Otherwise | Return the document |

Error identities (observed, static initializers [`0x10148e4cc`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0002/functions/0x10148e4cc.c)
and [`0x101535400`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0002/functions/0x101535400.c)):
`0x10148229c` raises localized key `sErrorDocumentCorruptWhileReading`
(global `0x106f4f708`) with the document name and the detail; `0x101488e64`
wraps it for a C-string detail. `0x101488ec0` raises
`sErrorDocumentIsFromNewerVersion` (`0x106f4f720`) with the document name.
The specific form uses `sErrorDocumentIsFromSpecificNewerVersion`
(`0x106f50538`) with the document name and a version string. `Languages.alp`
is opaque, so the user-visible texts are unknown.

Observed ([n2-0005 `0x101528c84`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0005/functions/0x101528c84.c)):
`0x101528c84` asks `0x101528e2c` for the Creator-derived version. It raises
the generic newer-version error when that is empty and the specific one
otherwise. At step 2's family branch the version is the same Creator remainder,
or `<a>.<b>` when the remainder is empty.

`0x101514e30` (pseudocode, [n2-0005](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0005/functions/0x101514e30.c))
requires digits, `.`, digits, `_`, digits and then the end of the string, with
no overflow check. A value such as `garbage` fails step 2 and falls through to
the stored corrupt error.

Current (major, minor) operands. The Creator-aware entry sets `+0x58`/`+0x5c`
from `0x1011c41c4`/`0x1011c41fc`. These return app-info fields `+0x120`/`+0x124`,
which `0x1011c1c24` fills with `std::stoi` of the first two groups of the regex
`(\d+)\.(\d+)(?:\.(\d+))?…` applied to `12.4.3` (pseudocode). Inferred values:
(12, 4). The general entry never sets them (disassembly of `0x101484108`
to the call at `0x101484204`). The constructor `0x1015286a4` does not
initialize them either, and the allocator `0x1012d9850` uses a pool or `malloc`.
On the general entry, step 2's family comparison therefore reads
**indeterminate** values.

Static derivation for MinorVersion values without a schema file:

| MinorVersion | Creator-aware entry | General entry |
| --- | --- | --- |
| `12.0_12403` (above the newest 12.0 translator, 12402) | Newer-version | Newer-version: the family test or the scan fires whatever the operands |
| `13.0_13000` (newer family, no files) | Newer-version (13 > 12) | Unknown: newer only if the indeterminate operands compare lower; otherwise corrupt |
| `12.0_12050` (gap inside 12.0) | Corrupt (`Unsupported MinorVersion`) | Unknown |
| `garbage` | Corrupt | Corrupt |

The scan `0x101514f7c` lists `*.txt` in a `Schema` directory under an
app-supplied base. It parses each stem as `<a>.<b>_<c>` and keeps the largest c
for family (a, b) (corpus pseudocode). Inferred: it is the same shipped
directory `Contents/App-Resources/Schema`, whose 12.0 family ends at
`12.0_12402.txt` and has no `12.0_12050.txt` (directory listing on 2026-10-17;
[static schema table](document-container-static.md#schema-directory-and-version-cross-check)).

The `+0x60` path (disassembly, [n2-0005 `0x10152a570`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0005/functions/0x10152a570.json)):
for a versioned document, element names are resolved through the document's
schema object `+0xb0` (`0x10151479c`, untraced). An unknown element sets `+0x60`
when the document's SchemaChangeCount exceeds that schema's ChangeCount, then
throws `Unknown class '$1' encountered`. So an unknown element is reported as
"newer" only when SchemaChangeCount claims a later schema revision, and as
corrupt otherwise.

The general XML reader `0x101484108` also checks the returned document's class
against the class its caller expects. A mismatch raises the corrupt-document
error `Wrong class found. Expected a "{}" or subclass, found a "{}"`
(`0x101488490`, pseudocode). The expected class for File > Open is unknown.

## Creator and Revision

Observed ([n2-0002 `0x101528e2c`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0002/functions/0x101528e2c.c),
[`0x101429854`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/corpus/0x101429854.c)):
`0x101528e2c` tests whether Creator starts with the parser's expected prefix
(`+0x50`). If so it returns the rest of Creator, passed through `0x1014300e0`;
inferred to be trimming. If not, it logs
`The document hasn't been created by "<prefix>"` and returns an empty
string. It is called only on the newer-version paths, so Creator never causes a
refusal.

- On the Creator-aware entry the prefix is app-info `+0x80`. `0x1011c2bb0`
  builds it as `Ableton` + space + `Live` (pseudocode; inferred value
  `Ableton Live`). For `Creator="Ableton Live 12.4d1"` the version named is
  therefore inferred to be `12.4d1`.
- On the general entry the constructor sets the prefix to the shared empty
  string. If that is a non-null empty string, every Creator matches and the
  whole Creator is the version text; if it is null, the match fails and the
  generic message is used. Unknown.

Observed ([`0x101573d24`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/corpus/0x101573d24.c), pseudocode):
after a load through `0x1018536d4`, a non-empty Creator that does not start
with `Ableton ` triggers an internal `third-party-document` event with
`creatorname` and `drag-and-drop` fields. Nothing is refused. Whether the event
leaves the process is unknown.

## Runtime use of `Schema/*.txt`

The static half left open whether 12.4.3 reads `Schema/*.txt` at runtime. The
code says it does, on the version-check path; none of this was executed.

- Observed (pseudocode, [n2-0005 `0x101514954`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0005/functions/0x101514954.c),
  [n2-0003 `0x101514c6c`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0003/functions/0x101514c6c.c)):
  - The version check's schema lookup caches by MinorVersion.
  - On a miss it forms `<MinorVersion>.txt` and asks the resource location
    `0x101514864` whether the file exists. That location is `Schema` under a
    base path held in a global (`0x10142a21c`).
  - It opens and parses the file only if it exists. A missing file gives null,
    which is check 4 above.
  - Inferred: the base is `Contents/App-Resources`.
- Observed: `0x101514f7c` scans the directory for the newer-version test (above).
- Inferred: element names in a versioned document resolve against the class
  list of the schema file its MinorVersion names (`0x10152a570` → `0x10151479c`).
- Observed (pseudocode `0x101515c1c`, `0x101515ed8`, `0x101515508`):
  - At startup the current schema name is built as app-info `+0x20` (`12.0`),
    then `_`, then the decimal of `0x101470ef4()`. That function returns the
    number of the last translator registration.
  - `Schema/<name>.txt` is read for its ChangeCount. When a comparison
    (`0x1015176c4`, untraced) returns 2, the count is incremented.
  - The in-memory current schema, global `0x106e0d200`, is built from
    registered classes (`0x10147f9b4` → `0x101515628`).
  - Inferred: the current name is `12.0_12402`.
- Schema-file errors exist with untraced triggers:
  - `Live: Reading schema files failed: ` (`0x101515778`)
  - `No schema found` (`0x10152ff80`, a corrupt-document error)
  - `Schema: Current schema not found` (`0x101517c64`, `0x101517cc4`)
  - `Unsupported schema version` (string referenced by `0x1015300d4`)

## Writing on save

Observed (pseudocode with disassembly for the compression call,
[n2-0002 `0x101485240`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0002/functions/0x101485240.c),
[n2-0005 `0x1014338b0`](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/results/n2-0005/functions/0x1014338b0.json)).
`0x101485240` (assert text `ACompound::SaveXmlStream`) is the only function
that refers to `MajorVersion`, `MinorVersion` and `SchemaChangeCount` besides
the reader, and the only one that refers to `Revision`
([index-lookups.jsonl](../../analysis/ableton-live-12.4.3/r2/n2-container-v1/index-lookups.jsonl)).
It is therefore the single writer of this envelope.

1. **Compression level.** An argument of −1 means "look up an option" (a 32-byte
   key constant at `0x105815b1c`). If the option is absent the level is 6;
   otherwise it is clamped to 0–9.
2. **Stream.** `0x1014338b0` maps −1 to 6. A level of 0 disables deflate, so
   the bytes pass through uncompressed (flag `+0x28` cleared; the flush in
   `0x1014339e4` writes them directly). Any other level calls `0x1011995c0` with
   `(level, 8, 31, 9, 0, "1.3.1", 0x70)`. Inferred: zlib `deflateInit2_` with
   gzip wrapping. The image carries `deflate 1.3.1`.
3. **Declaration.** `0x1015170a8` writes `<?xml version="1.0" encoding="UTF-8"?>`.
4. **Root.** The writer emits `Ableton`.
5. **Attributes.** Only when the document class has the versioned flag, it writes
   in this order:
   - `MajorVersion` — literal 5.
   - `MinorVersion` — from `0x101515508`.
   - `SchemaChangeCount` — the current schema's ChangeCount, only if positive.
   - `Creator` — `Ableton ` + app-info `+0x50`.
   - `Revision` — app-info `+0xc8`.
6. **Body.** The document element follows.
